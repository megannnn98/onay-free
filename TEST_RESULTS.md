# ONAY! NearbyStopFragment — результаты тестов

## Этап 1. Чистая логика (JVM)

Запуск: `scripts/run_unit_tests.sh` (JUnit 5 console 1.11.4, `javac --release 11 -Xlint:all -Werror`).

| Класс | Тестов | Что проверяется |
|---|---|---|
| `NearestStopFinder` + `Haversine` | 16 | расстояние (нуль, симметрия, ~111 м на 0.001°, антимеридиан); ближайшая остановка; две остановки с одним названием остаются разными (по id); сортировка и лимит; радиус включительно; пустой и `null` список; нет координат пользователя; остановки без координат и с невалидными (NaN, вне диапазона, в том числе у полюса); равные расстояния по id; лимит ≤ 0 |
| `RoutesAtStopSelector` | 10 | только маршруты остановки; только тип 0 (автобус) и 1 (троллейбус); дубли; направления, обслуживающие остановку; оба направления; неизвестное направление не угадывается; маршрут без загруженных направлений; id без `RouteInfo` пропускается; пустые и `null` входы; сортировка 12, 12A, 38, 79, 121, A5 |
| `RouteHighlightState` | 8 | выбор, повторное нажатие снимает, переключение, `clear`, прозрачность выбранного и остальных, `retainOnly` при смене остановки |

Итог: **34 из 34 успешно**.

Мутационная проверка (`scripts/mutation_check.sh`, на копии, по одному мутанту): 14 мутантов, **убиты все 14** (радиус, tiebreak по id, диапазон широты, порядок сортировки, лимит, радиус Земли, фильтр типов, дедупликация, инверсия направления, угадывание направления, сортировка по числу, toggle, прозрачность, retainOnly).
Первый прогон выявил слабый тест: мутант без проверки диапазона широты выжил, потому что невалидная точка и так отсекалась радиусом. Добавлен тест у полюса; мутант убит.

Что проверено: только логика на JVM. На Android, на устройстве и в эмуляторе ничего из этапа 1 не запускалось.
