# Независимая установка ONAY Free рядом с официальным ONAY!

Цель: Android-пакет модификации `kz.onay.free`, оригинала `kz.onay`. Оригинальные DEX-классы остаются `kz.onay.*` — это **не** другой Java namespace, а другой *install identity*.

## Как это устроено

1. Объединить исходные split APK в один unsigned APK через APKEditor.
2. Декодировать манифест получившегося APK через apktool с `-r -s` (не декодировать ресурсы и DEX).
3. `scripts/patch_clone_manifest.py`: заменить только `<manifest package>`, собственные provider authorities, объявленные custom permissions, process/taskAffinity, явно развернуть относительные class names на старую базу `kz.onay.*`, изменить launcher label.
4. Собрать APK заново, сравнить побайтово DEX, native библиотеки, `assets/` и `res/` с исходным merged APK — любое изменение прерывает сборку.
5. Подписать своим ключом, проверить сертификат, пакет `kz.onay.free`, zipalign, split-маркеры, ABI.

## Что остается потенциально несовместимым

Изменение install package **не** переписывает все жестко заданные строковые литералы внутри DEX и сторонних библиотек. В рантайме могут использоваться старые authority / `BuildConfig.APPLICATION_ID` / app id, а также ключи Google Maps, Firebase, OAuth, Play Integrity, подпись сертификата, перенаправление deep link, ContentProvider, пуши, платежи и серверные package checks.

**Эти механизмы не гарантированно совместимы с новым package ID.** Автоматическая сборка проверяет целостность файла, не работоспособность интеграций. Нельзя объявлять эту сборку проверенной, пока не выполнены тесты ниже. Не пытаться обходить привязку к подписи сервиса: при несовместимости соответствующие функции должны быть отключены, заменены собственными интеграциями с законными ключами либо исключены.

## Приемочные проверки на Android

На чистом устройстве или отдельном тестовом профиле с копией данных:

1. Установить официальный ONAY! (`kz.onay`) из Google Play, записать версию и проверить, что он запускается. Не удалять официальное приложение ради теста.
2. Установить только **новый** `onay-free-*.apk` с пакетом `kz.onay.free`: `adb install -r onay-free-*.apk`.
3. Убедиться, что оба пакета существуют:
   ```sh
   adb shell pm list packages | grep -E '^package:kz\.onay(\.free)?$'
   ```
   Ожидаются **две** строки: `package:kz.onay` и `package:kz.onay.free`.
4. Запустить ONAY Free и проверить карту, ближайшую остановку, номера автобусов, обновления позиции, смену остановки и разрешения GPS.
5. Открыть официальный ONAY! и убедиться, что он по-прежнему работает с текущими данными.
6. Обновить **оригинальный** ONAY! через Play и убедиться, что оба пакета и данные ONAY Free сохранились.
7. Проверить лог:
   ```sh
   adb logcat -c
   adb shell monkey -p kz.onay.free 1
   adb logcat -d | grep -Ei 'FATAL EXCEPTION|ClassNotFoundException|SecurityException|Google Maps Android API|Firebase|IllegalArgumentException'
   ```
8. В оригинальной программе отдельно протестировать оплату; в модификации — только если она намеренно доступна из меню. Возможны ошибки сертификата/авторизации, которых статические тесты не обнаруживают.
9. Подписать следующую версию тем же **новым** ключом и проверить `adb install -r` без удаления данных ONAY Free.

## Старые версии

`v0.0.1` устанавливалась как `kz.onay`. На новую `kz.onay.free` обновление *поверх* невозможно — пакеты разные. Если на устройстве стоит старая модификация, для возврата официального ONAY! потребуется её удалить **только с согласия пользователя**. Данные не мигрируют автоматически.

## Условия выпуска

- GitHub Actions тесты и реальная сборка должны пройти.
- Обязателен ручной smoke test на ARM64 Android.
- До успешной проверки — только `prerelease`, без заявлений о полной совместимости.
- Ключ подписи `kz.onay.free` и пароль должны храниться в безопасной резервной копии, иначе будущие обновления будут требовать удаления приложения.
